# Arabic i18n + RTL Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a runtime-switchable Arabic translation with full RTL layout mirroring to every page of the InVox frontend, toggled from Settings, with numbers staying Western-digit in both languages.

**Architecture:** One codebase, no duplicated pages/routes. `react-i18next` provides `t()` calls that replace hardcoded strings in place; two JSON dictionaries (`en.json`/`ar.json`) hold the actual text. `dir="rtl"` on `<html>` (driven by the chosen language) flips Tailwind's logical-property utility classes app-wide with no per-component direction logic, once physical classes are migrated to logical ones.

**Tech Stack:** React 18, react-router-dom 6, Tailwind CSS 3.4 (logical utilities), `react-i18next` + `i18next` (new dependencies).

**Spec:** [docs/superpowers/specs/2026-09-04-arabic-i18n-design.md](../specs/2026-09-04-arabic-i18n-design.md)

## Global Constraints

- Every page/component in scope gets both string extraction and RTL class conversion in the **same** pass — never touch a file twice.
- Numbers stay Western-digit: never change `Intl.NumberFormat('en-US', ...)` / `toLocaleDateString('en-US', ...)` calls in `lib/utils.js` to an `'ar'` locale.
- Dates are **not** localized (no Arabic month names) — out of scope per the spec's explicit non-goal.
- Language preference key: `localStorage.invox_language` (`"en"` default, `"ar"`).
- Translation key files: `frontend/src/i18n/locales/en.json` and `ar.json` — one flat pair of files, nested by namespace, no per-page files.
- Shared/reused strings live under the `common` namespace (see Task 1) — a page task references `common.*` instead of re-declaring "Save" or "Draft" again.

### RTL Tailwind class conversion table (apply wherever present, every task)

| Physical (remove) | Logical (use instead) |
|---|---|
| `ml-N` | `ms-N` |
| `mr-N` | `me-N` |
| `pl-N` | `ps-N` |
| `pr-N` | `pe-N` |
| `left-N` | `start-N` |
| `right-N` | `end-N` |
| `border-l`, `border-l-N` | `border-s`, `border-s-N` |
| `border-r`, `border-r-N` | `border-e`, `border-e-N` |
| `rounded-l-N` | `rounded-s-N` |
| `rounded-r-N` | `rounded-e-N` |
| `text-left` | `text-start` |
| `text-right` | `text-end` |

Inline `style={{ left: ... }}` / `style={{ right: ... }}` / `style={{ borderLeft: ... }}` cannot use these utilities — convert those specific spots to conditional JS keyed on `document.documentElement.dir === 'rtl'` (see Task 1's `getDirection()` helper), noted per-task where they occur.

### Verification convention (every task, not repeated per-step below)

This is a visual feature — "the file compiles" is not sufficient verification. Every task's last two steps are:
1. Start the frontend dev server if not already running (`npm run dev` from `frontend/`), open the affected page in the browser, confirm it renders correctly in **English** (nothing regressed).
2. Open Settings → Company Profile, switch language to **العربية**, return to the affected page, confirm: text is translated, layout is mirrored (RTL), Arabic renders with real glyphs (not fallback boxes), and any visible numbers are still Western-digit.

- [ ] **Step 3: Create the i18next config**

`frontend/src/i18n/index.js`:
```js
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'
import en from './locales/en.json'
import ar from './locales/ar.json'

const STORAGE_KEY = 'invox_language'

export function getStoredLanguage() {
  return localStorage.getItem(STORAGE_KEY) || 'en'
}

export function setStoredLanguage(lang) {
  localStorage.setItem(STORAGE_KEY, lang)
}

export function getDirection() {
  return document.documentElement.dir === 'rtl' ? 'rtl' : 'ltr'
}

i18n
  .use(initReactI18next)
  .init({
    resources: {
      en: { translation: en },
      ar: { translation: ar },
    },
    lng: getStoredLanguage(),
    fallbackLng: 'en',
    interpolation: { escapeValue: false },
  })

export default i18n
```

export function formatRelative(dateStr) {
  if (!dateStr) return '—'
  const d = new Date(dateStr)
  const now = new Date()
  const diff = Math.floor((now - d) / 1000)
  if (diff < 60) return i18n.t('topbar.justNow')
  if (diff < 3600) return i18n.t('topbar.minutesAgo', { count: Math.floor(diff / 60) })
  if (diff < 86400) return i18n.t('topbar.hoursAgo', { count: Math.floor(diff / 3600) })
  if (diff < 2592000) return i18n.t('topbar.daysAgo', { count: Math.floor(diff / 86400) })
  return formatDate(dateStr)
}
